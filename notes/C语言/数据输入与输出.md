# 数据输入与输出（C 语言）

> **面试主线：**先区分“字符 / 格式化 / 字符串”三类 I/O；再说明**返回值、缓冲区、边界与错误处理**。能讲清这些，才是工程化的 C 语言表达。

## 1. 总览：选择哪个函数？

| 场景 | 推荐 API | 核心理由 |
| --- | --- | --- |
| 读写一个字符 | `getchar / putchar`（或 `fgetc / fputc`） | 能显式识别 `EOF` |
| 按格式输出 | `printf` | 类型与格式必须匹配 |
| 按格式解析结构化输入 | `scanf`（严格检查返回值） | 适合格式确定的数据，不适合直接接收整行文本 |
| 读一整行 | `fgets` | 有长度上限，首选 |
| 输出字符串/一行 | `fputs / puts` | `puts` 会自动追加换行 |
| 拼装到内存缓冲区 | `snprintf` | 可限制写入长度，避免溢出 |

> `stdin`、`stdout`、`stderr` 分别是标准输入、标准输出、标准错误。交互式终端常是**行缓冲**：通常按下回车后，程序才读到一行。

## 2. 字符输入与输出

### 2.1 常用函数

```c
int getchar(void);             // 等价于 fgetc(stdin)
int putchar(int c);            // 等价于 fputc(c, stdout)
int fgetc(FILE *stream);
int fputc(int c, FILE *stream);
```

- `getchar/fgetc`：成功时返回一个转换为 `unsigned char` 后的值（0～`UCHAR_MAX`）；到达文件末尾或发生错误时返回 `EOF`。
- `putchar/fputc`：成功返回写出的字符；失败返回 `EOF`。
- `putchar` 的参数虽然是 `int`，实际只写入转换为 `unsigned char` 后的字符。

### 2.2 高频面试题：为什么 `getchar()` 的返回值要用 `int` 接收？

```c
int ch;
while ((ch = getchar()) != EOF) {
    putchar(ch);
}
```

**结论：为了让“任意字节值”和“结束/错误标记 EOF”不冲突。**

1. 字符数据的取值可能覆盖 `0 ~ UCHAR_MAX`，其中也包括 `0xFF`。
2. `EOF` 是一个负的 `int` 常量（通常为 `-1`），表示文件结束或读取错误。
3. 若先存进 `char` 或 `unsigned char`，会丢失 `EOF` 的语义，甚至把合法字节 `0xFF` 误判为 EOF。

**反例：**

```c
char ch;                         // 错误：可能无法区分 0xFF 与 EOF
while ((ch = getchar()) != EOF) { /* ... */ }
```

读取成功后若确实需要字符，再转换：`char c = (char)ch;`。需要区分“文件结束”和“读错误”时，在循环后配合 `feof(stdin)`、`ferror(stdin)` 判断。

## 3. 格式化输出：`printf`

### 3.1 格式串结构

```text
%[flags][width][.precision][length]conversion
```

例如：`%08.2f` 表示：用 `0` 填充、最小宽度 8、小数点后 2 位、按 `double` 输出。

| 分类 | 常见内容 | 作用 |
| --- | --- | --- |
| 标志 `flags` | `-`、`+`、空格、`0`、`#` | 对齐、符号、填充、前缀 |
| 宽度 `width` | `8`、`*` | 最小字段宽度 |
| 精度 `.precision` | `.2`、`.*` | 浮点小数位；字符串最大输出字符数 |
| 长度 `length` | `hh`、`h`、`l`、`ll`、`z`、`L` | 指定实参类型 |
| 转换符 | `d/i/u/x/o/c/s/p/f/e/g` | 指定输出方式 |

### 3.2 高频转换符与类型匹配

| 输出 | `printf` 格式 | 实参类型要点 |
| --- | --- | --- |
| `int` / `unsigned int` | `%d` / `%u` | 整数默认提升后传入 |
| `long` / `long long` | `%ld` / `%lld` | 长度修饰符必须对应 |
| `size_t` | `%zu` | 不要假定它等于 `unsigned long` |
| 指针 | `%p` | 传入 `(void *)ptr` 最稳妥 |
| `char` | `%c` | 输出一个字符 |
| `char *` 字符串 | `%s` | 必须指向以 `\0` 结尾的有效字符串 |
| `double` | `%f` | 可用 `.2f` 控制小数位 |

**面试表达：**`printf` 是可变参数函数，编译器无法仅靠函数原型校验所有实参；格式串和实参类型不匹配会导致**未定义行为**。实践中打开编译器格式告警，例如 GCC/Clang 的 `-Wall -Wextra -Wformat=2`。

### 3.3 安全与边界

```c
char name[16] = "Ada";
printf("%s\n", name);          // 正确：格式串是常量
// printf(name);                // 错误：存在格式化字符串漏洞

char buf[32];
int n = snprintf(buf, sizeof buf, "id=%d", 123);
if (n < 0 || n >= (int)sizeof buf) {
    /* 编码失败或输出被截断 */
}
```

- 不把外部输入直接作为格式串；应使用 `printf("%s", input)`。
- `sprintf` 无长度限制，容易缓冲区溢出；优先 `snprintf`。
- `%n` 会向指针所指位置写入已输出字符数；业务代码通常无需使用，也不要让外部格式串控制它。

## 4. 格式化输入：`scanf`

### 4.1 本质与返回值

`scanf` 按格式串从 `stdin` **解析 token**，返回“成功赋值的项目数”；输入结束或发生读取错误且尚未完成赋值时可返回 `EOF`。

```c
int age;
if (scanf("%d", &age) != 1) {
    /* 解析失败：不能继续假定 age 有效 */
}
```

> **面试必答：**不能只调用 `scanf` 而不检查返回值；否则非法输入会使目标变量保持旧值，错误字符仍滞留在输入流，循环可能反复失败。

### 4.2 格式符与修饰符

除少数差异外，转换符含义与 `printf` 相近；但 `scanf` 传的是**变量地址**，且长度修饰符的含义必须严格匹配。

| 目标变量 | 正确示例 |
| --- | --- |
| `int i` | `scanf("%d", &i)` |
| `unsigned int u` | `scanf("%u", &u)` |
| `long l` / `long long ll` | `%ld` / `%lld` |
| `float f` | `scanf("%f", &f)` |
| `double d` | `scanf("%lf", &d)` |
| `long double ld` | `scanf("%Lf", &ld)` |
| `char c` | `scanf("%c", &c)` |
| `char s[20]` | `scanf("%19s", s)` |

**易错点：**`printf("%f", d)` 传 `double`；而 `scanf("%f", &f)` 接收 `float *`，读取 `double` 才用 `%lf`。原因是可变参数调用中，`float` 会提升为 `double`，但指针不会发生这种提升。

### 4.3 空白字符规则与“吃掉换行”

- 格式串中的空格、换行、制表符会匹配并跳过任意多个空白字符。
- 除 `%c`、`%[`、`%n` 外，多数转换（如 `%d`、`%s`）也会跳过前导空白。
- `%c` **不跳过**空白，因此紧跟数字读取时往往读到前一次输入遗留的 `'\n'`。

```c
int n;
char op;
scanf("%d", &n);
scanf(" %c", &op);              // 格式串前的空格主动跳过空白
```

### 4.4 宽度、抑制赋值与扫描集

```c
char word[20], line[80];
scanf("%19s", word);            // 宽度 = 数组容量 - 1，防溢出
scanf(" %79[^\n]", line);      // 读取至换行；仍不如 fgets 直观、稳健
scanf("%*d");                   // 读取一个整数但不赋值、不计入返回值
```

- 对 `%s` 和 `%[` **必须给宽度**，预留 1 字节给结尾 `'\0'`。
- `%s` 遇空白停止，不能读取含空格的姓名或整行文本。
- `%[]` 是扫描集；`%[^\n]` 表示读取非换行字符。空行会使其匹配失败，边界处理繁琐。

## 5. 如何正确处理输入残留（“清垃圾”）

### 5.1 残留从哪里来？

用户输入 `123↵` 时，`scanf("%d", &n)` 只消费 `123`，换行符通常仍留在 `stdin`。下一次 `getchar()` 或 `scanf("%c")` 就可能立即得到该换行符。

### 5.2 推荐策略：统一用 `fgets`，再解析

这是交互式程序最稳健、最容易维护的做法：

```c
#include <stdio.h>
#include <stdlib.h>

char line[64];
if (fgets(line, sizeof line, stdin) != NULL) {
    char *end;
    long value = strtol(line, &end, 10);
    if (end == line) {
        /* 没有解析出数字 */
    } else {
        /* 可继续检查 end 后仅剩空白/换行，防止接受 12abc */
    }
}
```

优点：一次读取一整行，输入边界明确；可通过 `strtol` 的 `end` 指针、`errno` 做完整校验。

### 5.3 必须混用时：显式丢弃当前行剩余内容

```c
void discard_rest_of_line(void) {
    int ch;
    while ((ch = getchar()) != '\n' && ch != EOF) {
        ;
    }
}
```

- 在 `scanf` 成功读取后调用，可丢弃本行剩余字符。
- 在 `scanf` 失败后，也应调用它，避免同一非法字符导致死循环。
- 不要用 `fflush(stdin)`：C 标准只保证它对**输出流**有效；在输入流上的行为不可移植。
- 也不要依赖 `scanf("%d\n", &n)` “吞换行”：格式串末尾空白会继续等待下一个非空白字符，交互时可能表现为阻塞。

## 6. 字符串输入输出：`gets`、`scanf`、`fgets`

| API | 能否读空格 | 是否限制长度 | 换行处理 | 建议 |
| --- | --- | --- | --- | --- |
| `gets(buf)` | 可以 | **不能** | 丢弃换行 | **禁止使用** |
| `scanf("%s", buf)` | 不可以 | 仅写了宽度才可以 | 前导空白跳过，遇空白结束 | 仅限单个无空格 token |
| `fgets(buf, size, stdin)` | 可以 | 可以 | 若读到换行，通常保留 | **读取文本首选** |
| `puts(buf)` | — | — | 自动追加换行 | 简单输出一行 |
| `fputs(buf, stdout)` | — | — | 不自动追加换行 | 精确控制输出 |

### 6.1 `gets` 与 `scanf` 的区别（标准面试回答）

1. **边界安全**：`gets` 不接收缓冲区长度，无法阻止溢出，已在 C11 中从标准库移除；绝不能使用。  
2. **分隔规则**：`gets` 原本读到换行为止，允许空格；`scanf("%s")` 以空白为分隔，只能读一个单词。  
3. **工程替代**：需要读一行使用 `fgets`；如需数字/复杂字段，再用 `strtol`、`strtod` 或 `sscanf` 解析。  

### 6.2 安全读取一行并移除换行

```c
char name[64];

if (fgets(name, sizeof name, stdin) != NULL) {
    name[strcspn(name, "\n")] = '\0';  // 需要 #include <string.h>
}
```

若输入行长度超过缓冲区，`fgets` 不会读到换行；此时应继续读取并丢弃余下字符，或明确提示用户输入过长。

## 7. 一分钟面试收束

> C 的输入输出重点不是“会调用 API”，而是管理**类型、边界、缓冲和失败路径**。读字符时用 `int` 保存返回值以区分 `EOF`；格式化 I/O 要保证格式符与实参类型一致并检查 `scanf` 返回值；文本输入优先 `fgets`，通过长度限制避免溢出；混用输入方式时，明确处理遗留换行，而不是使用不可移植的 `fflush(stdin)`。
