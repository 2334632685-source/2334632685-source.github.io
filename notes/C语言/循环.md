## 1. 全局认知：循环的四要素

任何循环都可拆为四件事：

1. **初始化**：循环变量或状态从哪里来；
2. **条件**：什么情况下继续；
3. **循环体**：本轮完成什么工作；
4. **更新 / 退出**：状态如何推进，何时终止。

~~~text
初始化 → 判断条件 → 循环体 → 更新状态
              ↑                 │
              └─────────────────┘
~~~

### 1.1 C 中的真与假

- 数值 `0` 为假，**非 0** 为真；
- 条件表达式可以是任意标量表达式；
- 推荐开启 `-Wall -Wextra -Werror`，尽早发现可疑条件。

~~~c
while (count) {     // 等价于 count != 0
    --count;
}

if (a = b) {}       // 赋值，条件值为 b：通常是 bug
if (a == b) {}      // 比较
~~~

条件中确需赋值时，显式加括号，表达意图：

~~~c
while ((ch = getchar()) != EOF) {
    /* ... */
}
~~~

### 1.2 审查循环的“四问法”

- **能进来吗**：初始化和首次条件是否符合预期？
- **能出去吗**：退出条件是否可达？每条路径是否推进状态？
- **不会越界吗**：下标、长度、空指针、整数溢出是否受控？
- **异常怎么办**：`break`、`return`、失败路径是否释放资源？

> [!tip] 记忆
> 循环可靠性 = **有边界、有进展、有退出、有清理**。

## 2. 循环结构选型总览

| 结构 | 执行特征 | 适用场景 | 优点 | 常见风险 |
|---|---|---|---|---|
| `while` | 先判断，可执行 0 次 | 次数未知、状态/输入驱动 | 条件即业务语义 | 更新遗漏导致死循环 |
| `do...while` | 先执行，至少 1 次 | 菜单、重试、先读后判 | 直接表达“至少一次” | 不该执行时仍会执行；尾部分号漏写 |
| `for` | 初始化、条件、更新集中 | 计数、数组遍历、范围明确 | 控制变量生命周期清晰 | 循环体内篡改计数器 |
| `for (;;)` / `while (1)` | 显式无限循环 | 服务线程、事件循环 | 适合由事件退出 | 退出与阻塞策略不明确 |
| `goto + 标签` | 直接跳转 | 多资源失败清理 | 减少重复释放 | 可读性差，不能替代常规循环 |

> **选型口诀**：次数确定用 `for`；次数不确定用 `while`；至少一次用 `do-while`；长期运行用无限循环 + 明确退出点。

## 3. while：条件驱动的首选

### 3.1 基本形式

~~~c
while (condition) {
    /* body */
}
~~~

先判断再执行，因此循环体可能一次也不执行。

~~~c
size_t i = 0;
while (i < len) {
    sum += arr[i];
    ++i;
}
~~~

### 3.2 典型场景：流式读取

~~~c
int ch;                         // 不能用 char 接收 getchar 的结果
while ((ch = getchar()) != EOF) {
    putchar(ch);
}
~~~

`getchar()` 返回 `int`，因为除字符值外还要表示 `EOF`；若使用 `char`，可能无法区分普通字节与 `EOF`。

### 3.3 面试表达

> 当循环次数由外部输入或运行时状态决定时，我优先选 `while`。同时把状态更新放在固定、醒目的位置，并检查 `continue` 和错误分支不会跳过更新，保证循环一定能推进。

## 4. do...while：至少执行一次

~~~c
do {
    /* body */
} while (condition);  // 注意这里必须有分号
~~~

~~~c
int choice;
do {
    printf("1. start  0. quit\n");
    scanf("%d", &choice);
} while (choice != 0 && choice != 1);
~~~

适用于“先做一次，再基于结果决定是否重试”，如输入校验、通信重传、交互菜单。

不适用于“条件不满足就绝不能操作”的场景，例如设备未就绪时，不应先访问设备再判断。

> **面试一句话**：`do-while` 的价值不是语法差异，而是将“至少执行一次”编码进控制流语义。

---

## 5. for：计数与遍历的首选

### 5.1 基本形式与执行顺序

~~~c
for (init; condition; step) {
    /* body */
}
~~~

执行顺序：`init`（仅一次）→ `condition` → 循环体 → `step` → 再判断条件。

~~~c
for (size_t i = 0; i < len; ++i) {
    process(arr[i]);
}
~~~

`for` 适合把初始化、边界和步进放在一行内，让读者快速知道遍历范围。

### 5.2 三个表达式都可省略

~~~c
for (;;) {
    /* 有意设计的无限循环 */
}
~~~

工程中常用于事件循环；退出由 `break`、`return`、错误路径或线程取消机制控制。

### 5.3 高频坑：无符号变量倒序

~~~c
for (size_t i = len - 1; i >= 0; --i) {  // 错误：i >= 0 恒为真
    /* ... */
}
~~~

`size_t` 是无符号类型，减到 0 后会回绕为很大的值。推荐：

~~~c
for (size_t i = len; i-- > 0; ) {
    process(arr[i]);
}
~~~

当 `len == 0` 时该循环不会进入。写倒序循环时，先确认长度为 0 的语义，再审查下溢。

### 5.4 for 与 while

~~~c
for (init; condition; step) {
    body;
}
~~~

大致等价于：

~~~c
init;
while (condition) {
    body;
    step;
}
~~~

但不能机械替换：`continue` 的跳转位置不同；此外 `for` 初始化的变量通常拥有更小、更清晰的作用域。

## 6. 无限循环、标签与 goto

### 6.1 无限循环的工程要求

~~~c
for (;;) {
    Event event = wait_event();  // 阻塞等待，避免空转
    if (event.type == EVENT_STOP) {
        break;
    }
    dispatch(event);
}
~~~

无限循环不是错误，但必须能回答：

1. **谁触发退出**：停止事件、取消标志、超时还是错误？
2. **空闲时怎么处理**：阻塞、休眠、等待中断，而非忙等占满 CPU；
3. **退出如何收尾**：锁、文件、内存、设备如何释放？

### 6.2 loop 不是 C 关键字

C 没有 `loop` 循环关键字；下面的 `loop` 仅是标签：

~~~c
loop:
    handle_once();
    goto loop;
~~~

这可以形成无限循环，但通常应改写为 `for (;;)` 或 `while (1)`，意图更清晰，也更便于维护。

### 6.3 goto 的合理边界：统一清理

`goto` 不宜用来模拟正常循环，但在 C 的多资源错误回滚中很有价值：

~~~c
int init(void) {
    int rc = -1;
    void *buf = malloc(BUF_SIZE);
    if (buf == NULL) {
        goto out;
    }
    if (open_device() != 0) {
        goto free_buf;
    }

    rc = 0;
    close_device();
free_buf:
    free(buf);
out:
    return rc;
}
~~~

使用原则：

- 跳转方向单向，并向清理出口收敛；
- 标签名体现资源状态，如 `free_buf`、`unlock`；
- 不跨越普通业务逻辑；
- 不可跳入含有变长数组（VLA）声明的作用域。

> **面试表达**：我不把 `goto` 当作常规流程控制工具；但在 C 的多资源失败清理中，单出口标签能降低重复释放和资源泄漏风险。

## 7. 辅助控制语句：break、continue、return

### 7.1 break：退出最内层循环或 switch

~~~c
for (size_t i = 0; i < len; ++i) {
    if (arr[i] == target) {
        found = true;
        break;          // 只退出当前 for
    }
}
~~~

- `break` 仅影响**最内层**的 `for / while / do-while / switch`；
- 不能一次跳出多层循环；
- 多层退出优先考虑抽取函数、状态标志，或在清理场景谨慎使用 `goto`。

### 7.2 continue：跳过本轮剩余语句

~~~c
for (size_t i = 0; i < len; ++i) {
    if (!is_valid(arr[i])) {
        continue;
    }
    consume(arr[i]);
}
~~~

关键区别：

- 在 `for` 中，`continue` 后会先执行 `step`，再判断条件；
- 在 `while` / `do-while` 中，`continue` 后直接进行条件判断。

因此，`while` 中把更新放在 `continue` 之后可能导致死循环：

~~~c
while (i < len) {
    if (arr[i] < 0) {
        continue;       // 错误：i 未增长
    }
    ++i;
}
~~~

修正：让每一条路径都推进状态。

~~~c
while (i < len) {
    if (arr[i] >= 0) {
        consume(arr[i]);
    }
    ++i;
}
~~~

### 7.3 return：结束整个函数

~~~c
int find_index(const int *arr, size_t len, int target) {
    if (arr == NULL) {
        return -1;
    }
    for (size_t i = 0; i < len; ++i) {
        if (arr[i] == target) {
            return (int)i;
        }
    }
    return -1;
}
~~~

`return` 离开当前函数，而不仅是循环。若函数持有锁、内存或文件，直接返回前必须清理，或转入统一 cleanup 路径。

| 语句 | 作用范围 | 典型用途 |
|---|---|---|
| `break` | 最内层循环 / switch | 已找到目标、收到退出事件 |
| `continue` | 当前迭代 | 跳过无效数据 |
| `return` | 当前函数 | 返回结果、传播错误 |
| `goto` | 同一函数的指定标签 | 统一资源清理（谨慎） |

## 8. 循环正确性：面试可讲的证明框架

### 8.1 循环不变式

**循环不变式**是每轮开始或结束时都成立的性质，是说明循环正确性的核心工具。

以顺序查找为例：第 `i` 次迭代开始时，目标不在区间 `[0, i)` 内。

~~~c
int find_index(const int *arr, size_t len, int target) {
    if (arr == NULL) {
        return -1;
    }
    for (size_t i = 0; i < len; ++i) {
        if (arr[i] == target) {
            return (int)i;
        }
    }
    return -1;
}
~~~

证明过程：

1. **初始化**：`i = 0` 时，空区间满足不变式；
2. **保持**：若 `arr[i]` 不是目标，检查后 `[0, i + 1)` 仍不含目标；
3. **终止**：当 `i == len`，整个数组已检查；未返回即表示目标不存在。

### 8.2 终止性

要能指出一个持续逼近边界的“度量”：如 `i` 从 0 单调递增，且受 `i < len` 限制。若说不清哪个量在推进，循环就可能无法终止。

### 8.3 复杂度表达

- 单层完整遍历：时间 `O(n)`，额外空间 `O(1)`；
- 两层完整嵌套：通常 `O(n²)`；
- 复杂度由实际迭代次数决定，不能只看代码嵌套层数。

> **面试回答模板**：该循环维持“已处理区间满足某性质”的不变式；循环变量单调推进且有上界，所以一定终止。每个元素最多处理一次，因此时间复杂度为 `O(n)`，额外空间为 `O(1)`。

## 9. 工程实践：从能跑到可靠

### 9.1 边界与类型

- 数组长度和下标优先使用 `size_t`，但警惕无符号下溢；
- 合法下标通常为 `0 ... len - 1`，不要写成 `i <= len`；
- 明确接口契约：`arr == NULL` 与 `len == 0` 的组合是否允许；
- 计数器可能溢出时，限制上界或使用足够宽的类型。

### 9.2 不在循环内重复做不变工作

~~~c
// 不推荐：每轮重复计算长度
for (size_t i = 0; i < strlen(s); ++i) {
    /* ... */
}

// 推荐：s 在循环中不变时，计算一次
size_t len = strlen(s);
for (size_t i = 0; i < len; ++i) {
    /* ... */
}
~~~

先保证正确性，再用数据证明性能瓶颈；不要为了“微优化”破坏可读性。

### 9.3 轮询与并发

~~~c
while (!ready) {
}   // 忙等：可能持续占用一个 CPU 核
~~~

应按场景换成中断、条件变量、信号量、事件等待或带超时的休眠。若 `ready` 被并发修改，必须使用正确同步原语；`volatile` 不能替代原子操作或锁，也不能建立完整的线程同步关系。

### 9.4 资源与提前退出

循环内获取资源后，必须审视每条 `break / continue / return` 路径。实用原则：

> **资源的获取、使用、释放应在结构上彼此靠近；复杂函数用统一 cleanup 出口。**

## 10. 高频面试题速答

### Q1：`while` 和 `do-while` 的区别？

`while` 先判断后执行，可能执行 0 次；`do-while` 先执行后判断，至少执行 1 次。依据是业务是否允许初始条件不满足时完全不执行。

### Q2：`for` 和 `while` 如何选择？

语义可互相改写，但应按意图选择：计数、遍历、边界明确时用 `for`；次数未知、由状态或输入决定时用 `while`。代码读起来更直观。

### Q3：`break` 和 `continue` 的区别？

`break` 结束最内层循环或 `switch`；`continue` 仅结束当前迭代。`for` 中 `continue` 后仍会执行步进表达式，`while` 中则直接重新判断条件。

### Q4：如何避免死循环？

保证循环变量在所有路径上向退出条件推进，重点检查 `continue`、错误分支和无符号下溢；永久循环则设计明确退出事件、超时或取消机制，并避免忙等。

### Q5：什么时候使用 goto？

普通业务流程不建议使用；C 的多资源初始化失败后，使用单向跳转到清理标签是合理实践，能避免释放逻辑重复和遗漏。

### Q6：`return` 能替代 `break` 吗？

可以在函数需提前结束时使用，但作用范围更大：它直接离开函数。若有待释放资源，必须先清理或走统一出口，不能仅为跳出循环而忽略资源生命周期。

## 11. 记忆卡片与自测

- **循环四要素**：初始化、条件、循环体、更新/退出。
- **结构选择**：未知次数 `while`；至少一次 `do-while`；计数遍历 `for`。
- **辅助控制**：`break` 退一层，`continue` 跳一轮，`return` 出函数。
- **正确性证明**：有不变式、有进展、有边界、有清理。
- **工程底线**：不越界、不空转、不泄漏、不依赖未定义行为。
