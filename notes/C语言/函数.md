# C 语言函数

> **一句话总览**：函数是把一段可复用的逻辑封装为“输入 → 处理 → 输出”的单元。它通过**声明**约定接口、通过**定义**实现逻辑、通过**调用**复用能力。

## 1. 函数的作用与基本用法

### 1.1 为什么要用函数

- **复用**：相同逻辑只写一遍，避免复制粘贴。
- **拆分复杂问题**：把一个大任务切分成职责单一的小任务。
- **提高可读性与可测试性**：函数名本身表达意图，函数可独立测试。
- **抽象接口**：调用方只关心“传什么、得到什么”，无需了解内部实现。

### 1.2 函数由哪几部分构成

```c
// 1. 声明（原型）：告诉编译器函数的名称、参数与返回类型
int add(int a, int b);

// 2. 定义：给出函数具体实现
int add(int a, int b) {
    return a + b;
}

// 3. 调用
int sum = add(3, 5);
```

| 概念 | 含义 | 面试关键词 |
| --- | --- | --- |
| 返回类型 | 函数执行结束后交给调用者的数据类型；无返回值用 `void` | 类型匹配 |
| 形参 | 定义中接收数据的变量，如 `a`、`b` | 局部变量 |
| 实参 | 调用时实际传入的数据，如 `3`、`5` | 值传递 |
| 函数声明 | 通常放在头文件；可在定义前被调用 | 接口、编译期检查 |
| 函数定义 | 必须且只能有一个（`static` 函数例外仅在本文件可见） | 链接、符号 |

### 1.3 参数传递：C 只有值传递

C 语言**所有参数传递都是值传递**：调用时会把实参的值复制给形参。

```c
void swap_wrong(int a, int b) { // 交换的只是副本
    int temp = a; a = b; b = temp;
}

void swap(int *a, int *b) {     // 传入地址的副本，通过地址修改原对象
    int temp = *a; *a = *b; *b = temp;
}
```

> 常见误区："传指针就是引用传递"不准确。传递的仍然是**指针值的副本**；只是该副本指向原对象，因此可借助解引用修改原对象。

### 1.4 作用域与生命周期

- **局部变量**：在函数块内可见；进入代码块时创建，离开代码块后失效（自动存储期）。
- **`static` 局部变量**：作用域仍限函数内，但生命周期贯穿整个程序运行期；未显式初始化时为 `0`。
- **全局变量**：生命周期贯穿程序运行期；应谨慎使用，避免隐式依赖和并发问题。

```c
int next_id(void) {
    static int id = 0; // 只初始化一次，多次调用会保留值
    return ++id;
}
```

**记忆**：`scope`（能在哪里访问）与 `lifetime`（活多久）是两件不同的事。

## 2. 指针函数：返回指针的函数

### 2.1 定义与辨析

**指针函数**是“返回值类型为指针”的函数：

```c
int *find_max(int *a, int *b) {
    return (*a > *b) ? a : b;
}
```

它与**函数指针**不同：

| 名称 | 本质 | 示例 |
| --- | --- | --- |
| 指针函数 | 函数，返回一个地址 | `int *f(void);` |
| 函数指针 | 指针，保存函数的地址 | `int (*fp)(void);` |

**口诀**：`*` 靠函数名，返回指针；`*` 把函数名括起来，变量是函数指针。

### 2.2 返回指针时的生命周期问题

返回的地址必须在函数返回后依然有效。最危险的错误是返回局部自动变量的地址：

```c
int *bad(void) {
    int x = 10;
    return &x; // 错误：函数结束后 x 的生命周期已结束，悬空指针
}
```

可安全返回的常见对象：

1. **调用者传入对象的地址**：如 `find_max`。
2. **静态存储期对象的地址**：`static` 局部变量或全局变量的地址。
3. **动态分配内存的地址**：如 `malloc` 的返回值；调用者须负责 `free`。
4. **字符串字面量地址**：可读但不要修改。

```c
int *create_int(int value) {
    int *p = malloc(sizeof *p);
    if (p != NULL) *p = value;
    return p;  // 使用方检查 NULL，使用完 free(p)
}
```

> 大厂面试表达：**先判断函数返回的指针所指对象的存储期，再明确所有权。** 若是堆内存，要说明谁释放、何时释放；若是静态对象，要指出不可重入/线程安全风险。

## 3. 递归函数

### 3.1 核心结构

递归指函数直接或间接调用自身。一个正确的递归必须具备：

1. **递归关系（递推公式）**：大问题如何缩小成同类子问题；
2. **终止条件（base case）**：最小问题如何直接得到答案；
3. **趋近终止**：每次调用都必须向终止条件推进。

```c
// n! = n × (n - 1)!；0! = 1
long long factorial(int n) {
    if (n < 0) return -1;      // 非法输入的约定
    if (n <= 1) return 1;      // 终止条件
    return n * factorial(n-1); // 递归关系
}
```

### 3.2 如何分析递归

- **先写数学关系，再翻译成代码**，不要先“猜代码”。
- 每一层调用都要保存现场（参数、局部变量、返回地址）到调用栈。
- 递归深度为 `O(n)` 时，额外栈空间通常为 `O(n)`；深度过大可能导致**栈溢出**。

| 场景 | 递归优势 | 更适合迭代的原因 |
| --- | --- | --- |
| 树、分治、回溯 | 与问题结构天然一致，代码清晰 | — |
| 简单线性遍历、阶乘 | 写法简短 | 迭代可避免函数调用开销和栈风险 |

### 3.3 高频陷阱

- 没有终止条件，或递归参数没有收敛 → 无限递归、栈溢出。
- 忽略边界值：空链表、`n == 0`、负数、越界。
- 重复子问题导致复杂度爆炸：朴素斐波那契为 `O(2^n)`，可使用记忆化或迭代优化。

## 4. 函数指针与函数指针数组

### 4.1 函数指针

函数名在大多数表达式中会转换为函数入口地址，因此可以用函数指针保存并调用函数。

```c
int add(int a, int b) { return a + b; }

int (*op)(int, int) = add; // 也可写成 = &add
int result = op(2, 3);     // 等价于 (*op)(2, 3)
```

声明拆解：`int (*op)(int, int)` 中，`op` 是一个指针，指向“接收两个 `int` 并返回 `int`”的函数。

**类型必须兼容**：返回类型、参数个数及参数类型都应匹配，不能靠强制转换掩盖不匹配。

### 4.2 典型用途

- 回调函数：把“具体策略”交给调用方，例如排序比较规则。
- 分发/状态机：根据命令或状态选择不同处理函数。
- 模块化接口：以函数表模拟多态或驱动接口。

### 4.3 函数指针数组

函数指针数组适合“同一类操作的多种实现”：

```c
int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }
int mul(int a, int b) { return a * b; }

int (*ops[])(int, int) = { add, sub, mul };
int value = ops[2](4, 5); // 20，调用 mul
```

> 记忆方法：`ops[]` 先表示“数组”，`(*ops[])` 表示“数组元素是指针”，后面的 `(int, int)` 表示“指向函数”。

## 5. `qsort`：函数指针作为回调

标准库排序函数原型：

```c
void qsort(void *base, size_t nmemb, size_t size,
           int (*compar)(const void *, const void *));
```

| 参数 | 含义 |
| --- | --- |
| `base` | 待排序数组首元素地址 |
| `nmemb` | 元素个数 |
| `size` | 单个元素大小，通常写 `sizeof array[0]` |
| `compar` | 比较函数：负数表示左值排前，`0` 表示相等，正数表示左值排后 |

### 5.1 整数升序示例

```c
#include <stdio.h>
#include <stdlib.h>

static int compare_int_asc(const void *lhs, const void *rhs) {
    int a = *(const int *)lhs;
    int b = *(const int *)rhs;
    // 不要写 return a - b;：大数相减可能发生有符号溢出
    return (a > b) - (a < b);
}

int main(void) {
    int a[] = {42, -3, 7, 7, 0};
    size_t n = sizeof a / sizeof a[0];

    qsort(a, n, sizeof a[0], compare_int_asc);

    for (size_t i = 0; i < n; ++i)
        printf("%d ", a[i]); // -3 0 7 7 42
    return 0;
}
```

### 5.2 结构体排序示例

```c
typedef struct {
    const char *name;
    int score;
} Student;

static int compare_score_desc(const void *lhs, const void *rhs) {
    const Student *a = lhs;
    const Student *b = rhs;
    return (b->score > a->score) - (b->score < a->score);
}

Student students[] = {{"Alice", 92}, {"Bob", 85}, {"Carol", 92}};
qsort(students, 3, sizeof students[0], compare_score_desc);
```

### 5.3 面试要点

1. `qsort` 用 `void *` 实现泛型；比较器负责把它转换回实际类型。
2. 比较器的返回值看**符号**，而不是要求返回 `-1/0/1` 本身。
3. `qsort` **不保证稳定性**：比较结果为 `0` 的元素相对顺序可能变化。
4. 比较函数必须满足一致的排序关系；不要在比较器中修改元素或依赖会变化的全局状态。

## 6. 面试速答卡

**Q：C 如何传引用？**  
A：C 没有语言级引用传递，只有值传递。需要修改调用者对象时传入其地址，并通过指针解引用修改。

**Q：能否返回局部变量的地址？**  
A：不能。局部自动变量在函数返回时生命周期结束，返回其地址会形成悬空指针。可返回堆内存、静态对象或调用者对象的地址，但要明确所有权与释放责任。

**Q：递归函数最重要的两个条件？**  
A：递归关系和明确的终止条件，并保证每层递归都向终止条件收敛。

**Q：`qsort` 的比较函数为什么不建议 `return a - b`？**  
A：可能发生整数溢出，破坏比较结果。应使用 `(a > b) - (a < b)` 这类只返回符号的写法。
