# C 语言数据类型与存储类别

> [!abstract] 面试总述
> 学 C 的数据类型，先抓住两条主线：**类型决定“数据如何表示与运算”**，**存储类别决定“对象何时存在、在哪里可见、能否跨文件访问”**。面试回答时按“分类 → 规则 → 陷阱 → 工程选型”展开，既完整又有逻辑。

## 1. 全景框架：先分清“类型”和“存储类别”

```text
C 的类型系统
├─ 基本类型（直接存储一个值）
│  ├─ 整数：_Bool、char、short、int、long、long long
│  │        └─ signed / unsigned
│  ├─ 浮点：float、double、long double
│  └─ 枚举：enum
├─ 派生/构造类型（由已有类型组合而成）
│  ├─ 指针、数组、函数
│  ├─ 结构体：struct
│  └─ 共用体：union
└─ 空类型：void

声明的其他维度
├─ 存储类别：auto、static、extern、register、_Thread_local
├─ 类型限定符：const、volatile、restrict、_Atomic
└─ 类型别名：typedef
```

- **类型（type）**：决定对象占用的表示方式、取值范围、可做的运算。
- **对象（object）**：运行时实际占用存储空间的实体，例如 `int x;` 中的 `x`。
- **存储类别**：不改变 `x` 是 `int` 的事实，而是描述它的生命周期和可见范围。

> [!tip] 一句话记忆
> **类型看“是什么”，存储类别看“活多久、谁能用”。**

## 2. 整数类型：面试最核心的部分

### 2.1 类型层级与标准保证

```c
char / short / int / long / long long
```

C 标准**不承诺每种类型在所有平台上的固定字节数**，只保证：

```c
sizeof(char) == 1
sizeof(char) <= sizeof(short) <= sizeof(int)
             <= sizeof(long) <= sizeof(long long)
```

其中，`sizeof(char)` 恒为 1，但一个字节有多少位由 `CHAR_BIT` 决定；标准仅保证 `CHAR_BIT >= 8`，现代主流平台通常为 8 位。

| 类型 | 标准保证的最小位数 | 常见 32 位 | 64 位 Linux（LP64） | 64 位 Windows（LLP64） |
|---|---:|---:|---:|---:|
| `char` | 8 | 1 B | 1 B | 1 B |
| `short` | 16 | 2 B | 2 B | 2 B |
| `int` | 16 | 4 B | 4 B | 4 B |
| `long` | 32 | 4 B | 8 B | 4 B |
| `long long` | 64 | 8 B | 8 B | 8 B |
| 指针 | — | 4 B | 8 B | 8 B |

**面试表达：**“我不会假设 `int` 永远是 4 字节。标准只规定下限和相对关系；具体宽度取决于编译器和 ABI。64 位 Linux 常见 LP64，64 位 Windows 常见 LLP64，所以跨平台代码尤其不能把 `long` 当作固定 64 位。”

### 2.2 `signed`、`unsigned` 与 `char`

除 `_Bool` 外，整数类型通常可用 `signed` 或 `unsigned` 修饰：

- N 位 `unsigned`：范围为 $0 \sim 2^N-1$；
- 常见补码机器上的 N 位 `signed`：范围为 $-2^{N-1} \sim 2^{N-1}-1$；
- `int` 等价于 `signed int`；`unsigned` 等价于 `unsigned int`。

```c
char          c;  // 是否有符号由实现决定
signed char   sc; // 明确有符号
unsigned char uc; // 明确无符号
```

> [!important] `char` 是高频易错点
> `char`、`signed char`、`unsigned char` 是三个不同类型。文本数据通常使用 `char`；二进制缓冲区、字节序列、位操作应使用 `unsigned char`，避免依赖普通 `char` 的符号性。

```c
int ch;
while ((ch = getchar()) != EOF) {
    /* 正确：int 能同时表示所有 unsigned char 值和 EOF */
}
```

不能用 `char` 接收 `getchar()` 的返回值，否则可能无法区分合法字节值与 `EOF`。

### 2.3 平台数据模型：理解 `long` 与指针

| 模型 | `int` | `long` | 指针 | 常见环境 |
|---|---:|---:|---:|---|
| ILP32 | 32 位 | 32 位 | 32 位 | 传统 32 位系统 |
| LP64 | 32 位 | 64 位 | 64 位 | 64 位 Linux / Unix |
| LLP64 | 32 位 | 32 位 | 64 位 | 64 位 Windows |

> **记忆：**LP64 中 “L 和 P 都是 64”；LLP64 中 “两个 L（`long long`）和 P 才是 64”。

### 2.4 工程选型：不要只看类型名

```c
#include <stdint.h>

uint8_t  flags;       // 二进制字节、寄存器字段
int16_t  sample;      // 明确宽度的采样值
uint32_t packet_id;   // 协议字段
uint64_t timestamp;   // 时间戳
```

| 需求 | 推荐类型 | 原因 |
|---|---|---|
| 普通计数、循环变量 | `int` | 通常是目标平台的高效自然宽度 |
| 数组长度、对象字节数 | `size_t` | 能表示任意对象大小 |
| 两个指针相减 | `ptrdiff_t` | 标准规定的指针差类型 |
| 恰好 N 位的协议/寄存器数据 | `intN_t` / `uintN_t` | 明确数据布局（实现提供时） |
| 至少 N 位 | `int_leastN_t` / `uint_leastN_t` | 保证最小位宽 |
| 至少 N 位且追求运算速度 | `int_fastN_t` / `uint_fastN_t` | 选择实现上更快的类型 |

> [!tip] 选型口诀
> **普通运算用 `int`，长度下标用 `size_t`，协议寄存器用 `uintN_t`。**

打印固定宽度整数，使用 `<inttypes.h>` 的格式宏，避免跨平台格式不匹配：

```c
#include <inttypes.h>
printf("%" PRIu32 "\n", packet_id);
```

### 2.5 整数运算规则与坑

#### ① 整数提升

`char`、`short` 等窄整数类型参与表达式时，通常会先提升为 `int`：

```c
uint8_t a = 200, b = 100;
int sum = a + b;       // 先提升为 int，结果是 300
```

因此 `uint8_t` 不代表“每一步计算都只保留 8 位”。

#### ② 有符号与无符号混合

```c
int a = -1;
unsigned int b = 1;

if (a < b) {           // 常见结果为假：a 被转换为很大的无符号数
    /* ... */
}
```

**工程原则：**比较前统一有符号性和位宽；不要让负数隐式转换为无符号数后参与判断。

#### ③ 溢出

- **无符号整数溢出**：按 $2^N$ 取模，属于标准定义行为；
- **有符号整数溢出**：属于未定义行为（UB），不能依赖“回绕”。

```c
#include <limits.h>

if (b > 0 && a > INT_MAX - b) {
    /* a + b 会溢出 */
}
```

#### ④ 位运算与移位

- 掩码应使用无符号常量，如 `1u << bit`；
- 移位量不能为负，且必须小于左操作数提升后的位宽；
- 负的有符号数右移的结果由实现决定；协议、寄存器操作优先用无符号类型。

#### ⑤ `sizeof` 与格式化输出

`sizeof` 的结果类型是 `size_t`，应使用 `%zu` 输出：

```c
printf("%zu\n", sizeof(int));
```

格式串必须与实参类型匹配；在 `printf`/`scanf` 这类可变参数函数中，类型不匹配可能触发未定义行为。

## 3. 其他基本类型

### 3.1 `_Bool`

`_Bool` 的取值只能是 0 或 1。实际项目中通常包含 `<stdbool.h>` 后使用更易读的 `bool`、`true`、`false`。

### 3.2 浮点类型

| 类型 | 常见大小 | 常见有效十进制位数 | 字面量示例 |
|---|---:|---:|---|
| `float` | 4 B | 约 6～7 位 | `1.0f` |
| `double` | 8 B | 约 15～16 位 | `1.0` |
| `long double` | 由实现决定 | 由实现决定 | `1.0L` |

浮点数不能精确表示多数十进制小数，比较时不应直接使用 `==`：

```c
#include <math.h>
if (fabs(a - b) < eps) {
    /* eps 应结合数据量级和业务允许误差确定 */
}
```

### 3.3 枚举 `enum`

```c
enum State {
    STATE_IDLE,
    STATE_RUNNING,
    STATE_ERROR = 100
};
```

枚举用于给一组离散整数值命名，提升可读性。其底层兼容整数类型和对象大小由实现决定，因此不应把裸 `enum` 直接当作稳定的网络协议或持久化格式。

## 4. 派生/构造类型：从“单值”到“组合数据”

### 4.1 指针：保存地址，不等于数组

```c
int x = 10;
int *p = &x;
```

- 指针大小由平台数据模型决定，通常与所指类型大小无关；
- `NULL` 表示空指针，不能解引用；
- 未初始化的指针是**野指针**；所指对象生命周期结束后仍被使用的是**悬空指针**；
- 指针运算以元素为单位，只能在同一数组对象范围及其尾后位置内进行。

```c
const int *p1 = &x;       // 不能通过 p1 修改 x
int *const p2 = &x;       // p2 不能改指向
```

**记忆方法：从变量名向外读。** `p1` 是“指向 const int 的指针”；`p2` 是“const 指针，指向 int”。

### 4.2 数组：连续元素集合

```c
int arr[10];
int *p = arr;

sizeof(arr); // 整个数组：10 * sizeof(int)
sizeof(p);   // 指针本身大小
```

数组表达式在多数场景会衰变为首元素指针；但在以下场景不会衰变：

1. `sizeof(arr)`；
2. `&arr`；
3. 用字符串字面量初始化字符数组。

函数形参中的 `int arr[]` 会调整为 `int *arr`，函数内无法据此得知数组长度，因此应显式传递长度：

```c
void process(int *arr, size_t len);
```

### 4.3 函数类型

函数类型由**返回类型 + 形参类型列表**构成：

```c
int add(int lhs, int rhs);
int (*op)(int, int) = add; // 函数指针
```

`void f(void)` 表示无参数；`void f()` 在 C 中表示参数未指定，二者含义不同。

### 4.4 结构体 `struct`：成员独立存储

```c
struct Packet {
    char  type;
    int   id;
    short len;
};
```

成员按声明顺序排列，但为满足对齐要求，编译器可能插入内部填充和尾部填充，所以结构体大小可能大于成员之和。

- 为节省内存，通常按对齐要求由大到小安排成员；
- 普通结构体不应直接作为网络报文或文件格式，还要处理填充、字节序和 ABI 差异；
- `#pragma pack` / `packed` 会削弱对齐，可能导致性能下降或非对齐访问异常。

### 4.5 共用体 `union`：成员共享同一段存储

```c
union Value {
    uint32_t u32;
    float    f32;
};
```

所有成员从相同地址开始，大小至少可容纳最大成员。工程上应以“标签 + union”记录当前有效成员；不要依赖跨成员读取实现可移植的类型重解释，位级转换优先使用 `memcpy`。

---

## 5. `void`：没有值的类型与通用对象指针

- `void func(void)`：函数无返回值，且无参数；
- `void *`：通用**对象指针**，可保存任意对象地址；解引用前必须转换为具体指针类型；
- 不能定义 `void` 对象；标准 C 也不允许 `sizeof(void)` 或对 `void *` 做指针算术。

## 6. 存储类别：`auto`、`static`、`extern`

### 6.1 回答这类题前，先给出三维定义

| 概念 | 关注点 |
|---|---|
| **作用域（scope）** | 名称在源代码的哪些区域可见？ |
| **存储期（storage duration）** | 对象从何时创建，何时销毁？ |
| **链接属性（linkage）** | 不同作用域或不同源文件的同名声明是否代表同一实体？ |

### 6.2 全局对照表

| 声明位置与写法 | 作用域 | 存储期 | 链接属性 | 未显式初始化时 |
|---|---|---|---|---|
| 块内 `int x;`（默认 `auto`） | 块作用域 | 自动 | 无 | 值不确定 |
| 块内 `static int x;` | 块作用域 | 静态 | 无 | 零初始化 |
| 文件级 `int x;` | 文件作用域 | 静态 | 外部链接（通常） | 零初始化 |
| 文件级 `static int x;` | 文件作用域 | 静态 | 内部链接 | 零初始化 |
| `extern int x;` | 取决于声明位置 | 由定义决定 | 外部链接（通常） | 本身不定义对象 |

> [!important] 核心关系
> **静态存储期不等于内部链接。** 普通全局变量也有静态存储期；文件作用域的 `static` 才使名称只在当前翻译单元可见。

### 6.3 `auto`：默认的局部变量

```c
void f(void) {
    auto int x = 1;
    int y = 2;  // 与 x 同为自动存储期，通常不写 auto
}
```

自动对象执行到声明处时开始生命周期，离开代码块后结束。它常被实现为栈对象，但“栈”只是常见实现方式，并非 C 标准语义。

### 6.4 `static`：两个场景、两层含义

**场景一：修饰局部变量，延长存储期。**

```c
int next_id(void) {
    static int id; // 仅初始化一次，程序结束时才销毁
    return ++id;
}
```

名字仍只有块作用域，但对象贯穿整个程序运行期。由于共享状态存在，函数可能不可重入，也可能存在线程安全问题。

**场景二：修饰文件作用域对象/函数，赋予内部链接。**

```c
// module.c
static int cache_size;
static void reset_cache(void) { }
```

其他 `.c` 文件无法引用这些符号。将模块私有实现声明为 `static`，是 C 语言实现封装、避免命名冲突的常用方式。

### 6.5 `extern`：声明在别处定义的实体

```c
// counter.h
extern int g_counter; // 声明，不提供对象定义

// counter.c
int g_counter = 0;    // 唯一定义，提供存储
```

- 头文件放 `extern` 声明；恰好一个 `.c` 文件放定义；
- 函数声明默认具有外部链接，通常不需要显式写 `extern`；
- `extern int x = 1;` 含初始化器，因此是**定义**；
- 文件级 `static` 对象只有内部链接，其他源文件不能通过 `extern` 使用它。

### 6.6 额外了解：`register` 与 `_Thread_local`

- `register`：对编译器提出高频访问建议；现代编译器通常会自主优化，实际较少使用。
- `_Thread_local`（C11）：线程存储期，每个线程拥有独立对象；它不等价于线程同步。

> [!tip] 存储类别口诀
> **`auto` 进块生、出块灭；局部 `static` 作用域不变、状态保留；文件级 `static` 仅本文件可见；`extern` 跨文件声明、定义唯一。**

## 7. 类型限定符：工程代码中经常出现

| 限定符 | 含义与注意事项 |
|---|---|
| `const` | 不能通过当前名称/指针修改对象，不等于对象绝对不可变 |
| `volatile` | 每次访问都必须按可观察访问处理，适合 MMIO、硬件/中断异步修改场景 |
| `restrict` | 承诺特定指针是访问对象的主要路径，帮助优化；违反承诺会产生未定义行为 |
| `_Atomic` | C11 原子类型基础，用于并发原子访问 |

> [!warning] `volatile` 不等于线程安全
> `volatile` 不保证原子性、不提供互斥，也不建立线程间内存顺序。多线程共享数据应使用 C11 原子操作或锁；内存映射寄存器/中断相关对象才是 `volatile` 的典型场景。

## 8. 面试高频问答（可直接背诵）

### Q1：`int` 一定是 4 字节吗？

**答：**不一定。C 标准只规定最小范围和相对大小，具体宽度由实现与 ABI 决定。现代桌面环境通常为 4 字节，但可移植代码应通过 `<limits.h>`、`sizeof` 或 `<stdint.h>` 确认。

### Q2：`char` 一定是 8 位吗？

**答：**不一定。`sizeof(char)` 一定为 1，但一个字节的位数由 `CHAR_BIT` 决定，标准只保证至少 8 位；绝大多数现代平台中才是 8 位。

### Q3：局部 `static` 与全局变量的区别？

**答：**二者都具有静态存储期且默认零初始化。局部 `static` 的名字仅在函数块内可见，用于跨调用保留状态；普通全局变量位于文件作用域，默认具有外部链接，可由其他源文件通过 `extern` 声明引用。

### Q4：`extern` 会分配内存吗？

**答：**单纯 `extern int x;` 通常仅声明，不分配存储；真正提供存储的是某处定义，如 `int x = 0;`。但 `extern int x = 1;` 含初始化器，因此本身就是定义。

### Q5：数组和指针相同吗？

**答：**不相同。数组是连续元素的集合，数组大小属于其类型；指针是保存地址的独立对象。数组只是在多数表达式中衰变为首元素指针，`sizeof(arr)`、`&arr` 等场景不会发生衰变。

### Q6：有符号与无符号溢出的区别？

**答：**无符号溢出按 $2^N$ 取模，属于定义良好的行为；有符号溢出是未定义行为，不能依赖其回绕结果。

### Q7：为什么结构体大小可能大于成员之和？

**答：**为满足成员访问和结构体数组元素的对齐要求，编译器会插入内部和尾部填充。跨平台传输不能依赖普通结构体的默认布局。
